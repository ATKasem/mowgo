# Batch 11 — Estimates (quote → approve → convert to job)

You are working in the MowGo repo at /opt/data/mowgo. This batch ships the **Estimates** feature on ALL THREE platforms: web (`client/src/`), iOS (`ios-native/`), and Android native (`client/android-native/`), plus the Supabase migration file.

## WHY THIS FEATURE (research-backed, 2026-08-03)

Competitor + operator research found the top unsolved pain points in lawn care software:
1. **Slow quoting** — operators quote from memory / "pocketbook math"; they need a 2-tap estimate: pick client → send.
2. **Estimates go stale** — "$289K sitting in uncontacted estimates" is an industry-wide stat; nobody follows up. MowGo's answer: visible status (Draft/Sent/Approved/Declined) + a "Nudge" action that copies a follow-up text to the clipboard for estimates sitting in Sent >3 days.
3. **Clunky software** — everything must reuse the EXISTING card/dialog/theme language of Invoices. No new design language.

## PRODUCT CONTRACT (same on all 3 platforms)

- **Estimates live on the Invoices screen** via a segmented control at the top: `Invoices | Estimates`. NOT a new bottom-nav tab (no tab renumbering).
- **Estimate fields:** client (required, pick from existing clients via the client picker), amount (DECIMAL), note (optional free text), status, timestamps.
- **Status flow:** `draft` → `sent` → `approved` | `declined`. Transitions:
  - Create with "Save Draft" → status `draft`.
  - Create with "Send" (primary) → status `sent` + `sent_at` set + **copies the estimate text to clipboard** so the operator can paste into SMS/email immediately (mirror the invoice copy-to-clipboard pattern).
  - Detail view: "Mark Approved" (sets `approved`, `approved_at`) and "Mark Declined" (sets `declined`, `declined_at`) for draft/sent estimates.
  - **"Convert to Job"** button appears ONLY when status == `approved`: creates a job for that client (status `scheduled`, `scheduled_date` = today) linked via `job_id`, then shows a success toast/snackbar "Job created". After conversion the estimate shows a "Converted ✓" indicator and the Convert button is disabled/hidden.
- **Amount UX (kills the math complaint):** when a client is picked, amount auto-fills from `client.rate`. Operator can edit it. No line items, no tax, no discounts — lawn estimates are flat. Keep it ONE number.
- **Stale-estimate nudge UX (kills the uncontacted complaint):** estimates with status `sent` and `sent_at` older than 3 days show an amber "Nudge" button. Tapping copies to clipboard: `Hi {name}, just checking in on your estimate for ${amount} from {date} — still want me to hold the spot? Happy to adjust anything. Thanks!` (use the estimate's note if set — no, keep the fixed nudge text, simple).
- **Estimate text for clipboard (Send):** `Hi {name}, here's your estimate: ${amount} for lawn care. Valid for 30 days. Thanks!`
- **Status chips:** Draft (gray/muted), Sent (info/blue), Approved (success/green), Declined (danger/red). Reuse the existing status-chip styling from invoices/jobs (iOS Capsule+opacity pattern, Android StatusChip pattern, web badge classes).
- **Crew role:** crew members see NO estimates (mirror invoices: owner only, RLS `auth.uid() = user_id`). `loadEstimates` returns empty for crew; the Estimates segment shows its empty state.
- **Webhooks: DO NOT add estimate webhook events in this batch.** Out of scope.
- **AI chat: do not touch, do not re-add, do not mention.**

## DATA LAYER / SCHEMA

Supabase migration file to WRITE (do not apply — coordinator applies it): `supabase/migrations/012_estimates.sql`

```sql
-- Estimates (Batch 11)
CREATE TABLE IF NOT EXISTS estimates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
  client_id UUID REFERENCES clients(id) ON DELETE CASCADE NOT NULL,
  amount DECIMAL NOT NULL,
  status TEXT DEFAULT 'draft',
  note TEXT,
  sent_at TIMESTAMPTZ,
  approved_at TIMESTAMPTZ,
  declined_at TIMESTAMPTZ,
  job_id UUID REFERENCES jobs(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE estimates ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Estimates: owner only" ON estimates
  FOR ALL USING (auth.uid() = user_id);
```

Field names in ALL clients: `id, user_id, client_id, amount, status, note, sent_at, approved_at, declined_at, job_id, created_at`. Joined client name comes from `clients!left(name)` (web), `clients` ref (iOS), `clients!left(name)` decode (Android) — mirror how each platform joins invoices to clients.
