## F3 (LOW): updateLead throws when re-fetch fails after a successful update (LeadRepository.kt ~line 62-77)
`updateLead` does update → then select/re-fetch → `decodeList<Lead>().firstOrNull() ?: throw IllegalStateException(...)`. If the UPDATE succeeds but the re-fetch fails (transient network), it throws — and `convertLeadToClient`'s catch then DELETES the just-created client even though the lead WAS updated to won+client_id, leaving an orphaned lead referencing a deleted client.
**Fix:** Wrap the post-update re-fetch in try/catch. On failure, return a best-effort Lead reconstructed from the input + patch (apply the non-null patch fields onto the original `lead` argument — you have the id; the re-fetch is only for server-confirmed values). Only throw if the UPDATE itself failed (it already propagates). Keep the webhook using `updated.status`/`updated.clientId` — with the best-effort fallback these still hold the patched values.
