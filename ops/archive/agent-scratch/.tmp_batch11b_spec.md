## Product contract (already agreed — build exactly this)

- Estimates live on the Invoices screen via a segmented control: `Invoices | Estimates`. NOT a new bottom-nav tab.
- Fields: client (required, pick existing via the client picker), amount DECIMAL, note optional, status draft|sent|approved|declined, timestamps sent_at/approved_at/declined_at, job_id (set when converted).
- Flow: Save Draft → draft. Send (primary) → sent + sent_at + copy estimate text to clipboard. Detail actions: Mark Approved / Mark Declined (draft+sent). Convert to Job (ONLY approved): create job for that client, status scheduled, scheduled_date today, set estimates.job_id, toast/alert "Job created". Converted estimates show a "Converted ✓" caption and no Convert button.
- Amount auto-fills from client.rate when a client is picked (editable).
- Nudge: estimates with status sent and sent_at older than 3 days show an amber Nudge button → copies `Hi {name}, just checking in on your estimate for ${amount} from {date} — still want me to hold the spot? Happy to adjust anything. Thanks!` to clipboard.
- Estimate text copied on Send: `Hi {name}, here's your estimate: ${amount} for lawn care. Valid for 30 days. Thanks!`
- Status chips: draft=muted/gray, sent=info/blue, approved=success/green, declined=danger/red. Match each platform's existing chip styling (iOS capsule+opacity, Android StatusChip).
- Crew role: crew sees NO estimates (load returns empty; segment shows empty state).
- No webhook events for estimates. No AI chat.
