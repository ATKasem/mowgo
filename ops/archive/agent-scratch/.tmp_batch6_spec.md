## The backend contract (already live)

- Edge function URL: `https://vqgiynfrpsqddjrayczc.supabase.co/functions/v1/ai-chat`
- Auth: `Authorization: Bearer <user access token>` + `apikey: <BuildConfig.SUPABASE_ANON_KEY>` headers (the function calls supabase.auth.getUser() from the Bearer token — a user token is required, NOT the anon key alone)
- Request body: `{"messages": [{"role": "user"|"assistant"|"system", "content": "..."}, ...]}` (function slices to last 20 itself, but you should still send only the last ~20 from the client)
- Success: `{"reply": "..."}` (may be a JSON string; parse `reply` field)
- Errors: HTTP 401 (unauthorized), 429 (rate limited, "Too many requests. Please wait."), 400 (bad body), 500 (key not configured); body is JSON `{"error": "..."}`
- Rate limit: 30 req/min per user

## TASK 1 — ChatRepository (`data/ChatRepository.kt`, new)

Mirror TeamRepository structure (OkHttpClient + Json { ignoreUnknownKeys = true } + Dispatchers.IO).

- `suspend fun send(messages: List<ChatMessageDto>): String` — builds request to the edge function URL:
  - headers: Authorization "Bearer <accessToken>" (from AuthRepository.currentSession?.accessToken — throw IllegalStateException("Not authenticated") if null), apikey BuildConfig.SUPABASE_ANON_KEY, Content-Type application/json
  - body: `{"messages": [...]}` (last 20 messages)
  - non-2xx: parse `{"error": "..."}` and throw IllegalStateException with that message (fall back to "Server error (<code>)")
  - 2xx: parse `{"reply": "..."}` and return the reply string (if reply missing, return "Sorry, I couldn't process that.")
- Demo mode (when !SupabaseClientProvider.isConfigured): return a canned reply instead of hitting the network — e.g. `"Demo mode: I'm MowGo AI, your lawn care assistant. In the real app this connects to the AI backend."` (echo a simple canned response; no fake intelligence).
- `data class ChatMessageDto(val role: String, val content: String)` @Serializable — role values "system" | "user" | "assistant".
- System prompt: copy the iOS `systemPrompt` string VERBATIM (the lawn-care-only guardrail prompt in ChatService.swift lines 45-65).

## TASK 2 — ChatViewModel (`ui/screens/chat/ChatViewModel.kt`, new)

State machine mirroring iOS ChatService:
- `ChatUiState`: `messages: List<ChatMessage>` (id: Long or String, role, content), `isLoading: Boolean`, `error: String?`
- `ChatMessage` model (in the chat package, NOT @Serializable — UI only): id (use incrementing counter or UUID string), role ("user"/"assistant"), content, timestamp (for grouping/display if wanted)
- `send(text: String)`:
  - debounce: if isLoading, ignore
  - append user message; cap list at 100 (drop oldest)
  - build history: `[{"role":"system","content":systemPrompt}]` + last 20 messages (excluding the system msg from the count)
  - repository.send(history) → append assistant message with reply
  - on failure: append assistant message "⚠️ Connection error. Please try again." and set error (like iOS)
- `retry()` — if last message is the error message, re-send the user message that preceded it (nice-to-have; implement simply: keep the last user text in state, retry sends it)
- `clearChat()` — cancel in-flight, clear messages, clear error
- Cancel in-flight on new send (mirror iOS currentSendTask pattern — store the Job and cancel() before starting a new one)
- Keep it simple: no persistence of chat history across sessions (iOS doesn't persist either)

## KOTLIN COMPILE GOTCHAS (same list — all hit before in this repo)

- NO labeled returns inside non-inline lambdas (`return@AlertDialog` etc.). Use local vals + if-checks.
- Nullable mutable lists: wrap `(list ?: emptyList()).map { }`, never `listOf(x) + nullableList` directly.
- `java.time.*` explicit imports.
- Top-level `private` = file-private — cross-file composables must not be private.
- PullToRefreshBox / TopAppBar / FAB / ModalBottomSheet need `@OptIn(ExperimentalMaterial3Api::class)` where applicable.
- `collectAsStateWithLifecycle()` import: `androidx.lifecycle.compose.collectAsStateWithLifecycle`.
- OkHttp imports: `okhttp3.MediaType.Companion.toMediaType`, `okhttp3.RequestBody.Companion.toRequestBody` or `RequestBody.create(...)` (match TeamRepository style exactly).
- BuildConfig: `com.mowgo.app.BuildConfig` — SUPABASE_ANON_KEY and SUPABASE_URL fields exist.
- No new dependencies.
