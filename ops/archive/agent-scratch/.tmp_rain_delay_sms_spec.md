# Rain-Delay SMS + Reply Forwarding (spec)

**Status:** 🆕 — Aug 5, 2026
**Why:** The product's #1 promise ("one tap moves the schedule and texts every client") has no client-notification path. Landing copy claims it; nothing sends it. Hormozi lens: the notification IS the feature — moving dates silently leaves the pain intact.
**Platform split (Blasian's call):** Android app → device-native SMS from the operator's own number (free, replies go straight to the operator). iOS + web → Twilio shared number + reply forwarding (seamless both directions).

## Architecture

- **`send-rain-delay-sms`** (Supabase edge fn, JWT-protected, called by the app after jobs move)
  - Body: `{ jobIds: string[], targetDate: 'YYYY-MM-DD' }`
  - Loads profile (business_name), the moved jobs, their clients (name, phone)
  - Sends one SMS per client (deduped): `Hi {first}, this is {business}. Rain's coming, so we moved your service to {Thursday, Aug 6}. No action needed.`
  - From: `TWILIO_FROM` (MowGo shared toll-free number)
  - Upserts `sms_threads` (user_id, client_id, client_phone) so reply-forwarding can route
  - Fire-and-forget from the client — never blocks the rain-delay UI
- **`sms-inbound`** (Supabase edge fn, PUBLIC — Twilio webhook; validates X-Twilio-Signature)
  - Client texts MowGo number → forwarded to the owner's phone (`profiles.phone`) as `{Client name}: {body}`
  - Owner replies to MowGo number → routed to their MOST RECENT thread's client phone, body as-is
  - No thread found → 200 silent (log only)
  - MVP routing rule: most-recent-thread for owner replies (documented limitation)
- **Migration 018 `sms_threads`**: user_id, client_id, client_phone, last_activity, last_from; unique(user_id, client_id); RLS on, service-role only (mirrors route_audits)
- **Web wiring:** `Today.jsx applyRainDelay` → after `rainDelayJobs` succeeds → `supabase.functions.invoke('send-rain-delay-sms')` fire-and-forget; demo mode skips. New helper in `src/lib/data.js`.
- **Native:** iOS calls the same edge fn on rain delay (follow-up batch when app ships). Android uses device SMS via Capacitor plugin (follow-up batch; SEND_SMS runtime permission; no Twilio cost). Android users on web fall through to the Twilio path.
