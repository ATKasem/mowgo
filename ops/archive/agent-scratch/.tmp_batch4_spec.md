## KOTLIN COMPILE GOTCHAS (all previously hit in this codebase — follow these or CI fails)

- **No labeled returns inside non-inline lambdas**: `return@AlertDialog`, `return@onClick` → compile errors. Restructure with local vals + if-checks.
- **Nullable mutable demo lists**: `demoList = listOf(x) + demoList` or `.map{}`/`.filter{}` on a nullable receiver → compile errors. Always wrap: `(demoList ?: emptyList()).map { }` and reassign non-null.
- `java.time.Instant` needs explicit `import java.time.Instant` (other java.time classes don't leak it).
- **Top-level `private` = file-private**: any composable called across files (e.g. shared dialog) must not be private.
- `PullToRefreshBox` + `FilterChip` + `TopAppBar` need `@OptIn(ExperimentalMaterial3Api::class)`.
- `collectAsStateWithLifecycle()` import: `androidx.lifecycle.compose.collectAsStateWithLifecycle` (lifecycle-runtime-compose is wired).
- `viewModel()` import: `androidx.lifecycle.viewmodel.compose.viewModel`.
- ViewModels: plain `ViewModel()` subclass with `MutableStateFlow` + private setters; expose `StateFlow`. Use `viewModelScope.launch`. UI collects with `collectAsStateWithLifecycle()`.
- DataStore: `val Context.dataStore by preferencesDataStore(name = "settings")` — top-level, one instance per name.
- Supabase partial update: `client.from("profiles").update(mapOf("business_name" to name, "phone" to phone, "email" to email)) { filter { eq("id", userId) } }`. Insert/select via `decodeList<T>()`/`decodeSingle<T>()` — check supabase-kt 3.0.1 API: `from("profiles").select { filter { eq("id", userId) } }.decodeSingle<Profile>()` (wrap in try/catch — 406/no rows → return null).
- BuildConfig fields exist for version name: `BuildConfig.VERSION_NAME`, `BuildConfig.APPLICATION_ID` (or use `context.packageName`).
- Do not add new dependencies to libs.versions.toml — everything needed (datastore-preferences, material-icons-extended, coil) is already wired.
