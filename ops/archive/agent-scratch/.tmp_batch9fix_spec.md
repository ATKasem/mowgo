## FINDING 5 (MED) — Android: photo readBytes() OOM risk
`client/android-native/app/src/main/java/com/mowgo/app/ui/components/JobPhotoControls.kt:58` — `contentResolver.openInputStream(uri)?.readBytes()` loads the FULL original into memory, then decodes + compresses — large camera images can OOM despite the later inSampleSize decode.
Fix: decode bounds first, then decode a sampled bitmap, using the stream/FileDescriptor without a full `readBytes()`:
- Open the input stream once for bounds: `BitmapFactory.Options().apply { inJustDecodeBounds = true }` + `BitmapFactory.decodeStream(stream, null, opts)` (open a fresh stream from the uri for the actual decode).
- Compute `inSampleSize` from target 1600px (existing helper if present — reuse it).
- Reopen the stream, `BitmapFactory.decodeStream(stream, null, opts)` with sample size, then compress. Close streams in `finally`/`use`. Do not hold the full byte array.
- Keep camera path (FileProvider → File) as-is if it already decodes from file path (files don't OOM the same way — verify; only fix the uri/readBytes path).
